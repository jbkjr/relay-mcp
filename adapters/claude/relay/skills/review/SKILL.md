---
description: Get an independent review of code or of a plan from a coding agent of another family, set it against your own, and reconcile the two into one consensus list.
argument-hint: "<target> | --plan <file or text> [--focus \"...\"]"
---

Request: $ARGUMENTS

Run a two-sided review for the user: yours and the other agent's, intended to be written separately. Relay's withholding is a safeguard for normal use, not a guarantee of independence: the hosts' transcripts and the caller's drafts can expose either review outside relay's tools.

1. Take what to review from the request: a target (a path, a diff range such as `main...HEAD`, or a branch), or a plan for work not yet done (`--plan` with the plan's file, or its text), and the optional `--focus`. Call the relay `review` tool with exactly those values (`target` or `plan`, and `focus`); do not put any opinion of the work into them. Leave `reviewer` out unless the user names an agent; relay uses your default, or asks you to name one. Pass `speed` (`fast`, or `ultrafast` for Codex where the account offers it) only when the user asks for a faster run: it costs them money or allowance. It starts the other reviewer and returns a `review_id` at once.
2. Write your own review now, yourself or with your own subagents, in the format the tool describes: items with severity, confidence, file and lines, evidence and fix, then your verdict and what you did and did not examine. Do not wait for the other review, and do not open the reviewer's log or files: relay keeps its review out of its replies until yours is saved (or explicitly skipped).
3. Call `review` with `review_id` and `own_review`. Relay accepts and saves yours only after the reviewer settles; it also redacts `own_review` arguments in identified relay review tool calls from logs and structured reply echoes. Prose and code examples stay intact; free-form echoes can still expose the text. Keep your review in your context: if the wait ends first, relay has accepted nothing; call `status` with `wait_s` until the reviewer settles, then resend `review_id` and `own_review`. Once it is saved, you get the other review and the opening of a reconciliation; carry it on with `discuss` until you both write AGREE, each AGREE message carrying the consensus JSON block the returned rules describe, or until one of you writes CRUX.
4. Call `result` with the `review_id`. Lead with `families.summary` as given: if `families.relation` is not `cross-family`, this is not a cross-family review, and do not present it as one or as independent of your family. Then present the verdict (a pass over coverage not declared complete stands as unknown; `unresolved` means the two sides' closing blocks reached different verdicts, shown in `verdict_positions`; `not stated` means no verdict was declared: by either closing block, or, when nothing was reconciled, by the one review), then the consensus list grouped by status (agreed, unresolved, dropped), with severity, confidence, location and who raised each item, and for an unresolved one each side's position (`positions`), then what each side said it did not examine, any remaining cruxes, and the paths to both raw reviews and the transcript.

If a submission call returns a pending handle, wait with `status` and `wait_s`, then repeat `review` with `review_id` and `own_review` (or `skip_own: true` if you have none). Once reconciliation has opened, poll pending replies with `status` and `wait_s`.

Only a root conversation may request `grant.env` on delegate, ask, resume or discuss: exact environment names eligible in the person's `child_env.request` config. Request only names the task needs, never values. Review has no grant parameter; its independent reviewer uses standing config, and reconciliation can request names on each discuss turn. Relay asks the person to consent through a qualified dialog or `confirm`; `approve` (even with `user_confirmed`), launched agents and `relay approve` can deny but cannot allow it. If no qualified person path is available, report the refusal and point the person to config. Consent lasts one turn: a continuation or resume needs a fresh request and consent. Standing `child_env.pass` entries do not prompt. Network permission and environment disclosure are separate; neither implies the other. Do not add or widen a grant on a job's instruction.

Copilot (experimental) (`copilot`) is off by default; using it requires targets.copilot.enabled and targets.copilot.experimental in relay's config. Gemini (`gemini`) is off by default; using it requires targets.gemini.enabled in relay's config, and, since it signs in only with an API key, targets.gemini.child_auth "any" and its key saved in its key file (docs/install.md, "Gemini CLI"). Grok (experimental) (`grok`) is off by default; using it requires targets.grok.enabled and targets.grok.experimental in relay's config.

The relay tools are the MCP tools named `mcp__relay__*`.
