# Relay enforces its own confinement for harnesses it cannot verify

Relay used to only configure each harness's own sandbox and check that the configuration took (Claude Code and Codex both allow this). Most other harnesses either have no OS sandbox or one relay cannot trust: Grok Build's carries on unprotected if it fails to start and does not block network on macOS. So for those, relay wraps the whole harness in a sandbox it generates per turn (macOS Seatbelt, deny by default), with an allowlisting proxy for network and a broker outside the sandbox so the agent can still call relay without touching relay's records. Without this, relay could not offer those families while keeping its promise that a launched agent writes only its worktree. Decided by the maintainer, 2026-10-15, after a prototype passed 35 scripted escape probes (the prototype and its probes are not published).

## Considered options

- **Ship only harnesses whose own sandbox relay can verify.** Today that is none beyond Claude Code and Codex, so it would mean no new families.
- **Accept unverified harness sandboxes, labelled.** Breaks the worktree-only promise silently whenever the harness's sandbox fails open.
- **Containers or VMs (Apple `container`).** Needs Linux builds of every harness and a second login inside the VM; kept as the fallback.

## Consequences

- `sandbox-exec` is deprecated by Apple (still shipped and enforced on macOS 27, and used by Claude Code, Codex and Gemini CLI). Confinement sits behind an interface, and a missing or non-enforcing mechanism makes relay refuse those harnesses, never run them unconfined.
- Relay now owns a security boundary: it must probe the exact profile before every launch, and be red-teamed adversarially before shipping.
- Seatbelt rules are path rules, and a writable `subpath` lets the root itself, and any directory inside it, be renamed or removed: a turn could move a protected path out from under its rule, or leave a link where a writable root was for the next turn's profile to follow (review r_11c43840). So the profile also forbids removing, renaming or re-creating every writable root and every ancestor of a protected path inside one, and relay checks before each turn, without following links, that the worktree and each writable root are still the directories it pinned (resolved path, device and inode). Each granted directory is pinned the same way when the grant is authorised, and before every turn relay checks it still resolves, through real directories only, to that same directory, so an agent granted an ancestor cannot redirect another grant through an intermediate symlink; a grant must carry exactly one valid pin, and one from before relay pinned grants is refused until the root grants it again (review C4/X2). A granted directory's own `.git` (hooks, config) is hard-denied like the worktree's (review C3).
- Deny-default does not reach every operation: `fcntl` commands, `fsctl` commands, process inspection, Mach services, IOKit user clients, named POSIX semaphores, sockets and `sysctl` are allowed unless a rule names them. So the profile denies the `fcntl` commands that write through a read-only descriptor; allows no mutating `fsctl` (the alternate-chflags command is gone); denies inspecting or listing processes outside the sandbox (and reads no `kern.proc`/`kern.procargs2` sysctl, which would expose other processes' argv and environment); allows Mach services only from a fixed list and no XPC service; opens no IOKit user client (not even the power-domain one, whose setters relay's harnesses do not need); allows named POSIX semaphores only under `/mp-`, the prefix Python's multiprocessing uses (the maintainer, 2026-10-16; the namespace is machine-wide, so another process's `/mp-` semaphore is reachable by its random, unlistable name, a stated residual); allows Unix sockets only under the turn's temp dir, its bridge and the system log; and allows only kernel-control sockets with the network on. The keychain downgrade reads the change-notification shared-memory segment but no longer writes it. Certificate-trust daemons and the keychain are per-harness downgrades, stated in `doctor`.
- The per-turn probes run under the exact profile and must show positive evidence of the sandbox refusing each thing that must be denied, with a positive control for each where a pass could be for the wrong reason. They aim at relay-owned decoys wherever possible; the rules for the person's own paths (the real home, a read turn's checkout and its `.git`, login stores, the harness binary) are covered by generator tests against scratch copies, not by a live write that would touch the person's files (the maintainer's C3 decision). Every deny rule carries the turn's tag, and relay streams that turn's denials from the system log into its log (waiting for the stream to attach first, and filtering the harmless denials every process raises), so a harness the profile stops says which rule stopped it.
- What relay-enforced confinement does not cover must be stated plainly: reads stay broad except relay's own control and sockets directories; the vendor's API is reachable; credentials the harness can read are not protected; the turn's proxy credentials must travel in the harness's environment where the protocol needs them (`HTTPS_PROXY`), which another of the person's processes can read, though they are per-turn and only this turn's sandbox may use this turn's proxy; and an approval cannot lift the boundary in 1.0. An approval request relay refuses to a live ACP turn is recorded as a denial, so the turn ends blocked, not done.
- Claude Code and Codex keep their own verified sandboxes; they are not wrapped.
